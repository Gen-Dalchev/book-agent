# book-agent

Книжный агент — личный ассистент для чтения книг и статей: книги в EPUB, PDF и FB2 импортируются в markdown по частям.

## Установка

Нужен Node 24. Один раз в корне репо:

```
npm ci
```

Дальше — импорт книги одной командой, формат определяется сам: `npm run import -- книга.epub out/книга` (так же `книга.pdf`, `книга.fb2`, `книга.fb2.zip`).

## Импорт EPUB

Из корня репо:

```
npm run import -- книга.epub out/книга
```

Получится папка `out/книга/`:

- `book.md` — шапка и оглавление. В шапке по строке: Автор, Язык, Переводчик, Издатель, Год, ISBN, Глав, Частей, Сносок (число сносок во всех частях; 0 — если их нет); данные издания берутся из самого файла книги, чего в нём нет — «не указан». Переводчик — тот, у кого в файле роль переводчика (в «Автор» он не попадает); год — год издания из даты в файле (явно ненастоящий, вроде 0101, не пишется); ISBN — только настоящие, с верной контрольной цифрой, печатный и электронный через запятую. В оглавлении — номер части, заголовок главы или подглавы, имя файла, число слов (текст сносок считается, метки определений `[^N]:` — нет). По номеру просите в сессии чтения: «дай часть 003-02».
- `parts/` — текст книги в markdown, по частям в порядке чтения:
  - `001.md` — глава без подглав целиком;
  - `002-00.md`, `002-01.md`, `002-02.md`, … — глава с подглавами: `-00` — текст до первой подглавы (если он есть), дальше — подглава за подглавой.

В тексте частей заголовок главы — `#`, подглавы — `##`, мелкие заголовки — `###`; курсив и жирный сохранены, картинок и оформления нет. Внутри абзаца, пункта списка и цитаты пустых строк нет: строфы и переносы строк в одном абзаце исходника — одним переносом, чтобы абзац исходника был одним абзацем в счёте (раздел «Ссылки на место»).

Обложка и другие страницы без текста частями не становятся; их видно в «Пропущено» (ниже).

### Главы и подглавы по оглавлению книги

Глава — файл книги в порядке чтения, подглавы — по заголовкам внутри файла. Так и остаётся, если оглавление книги плоское, ведёт только на места внутри файлов (`c1.xhtml#s1`) или его нет.

Но у полных изданий часть книги обычно — страница с одним заголовком, а её главы — отдельные файлы. Если в оглавлении книги (EPUB 3 — документ навигации, EPUB 2 — NCX) у пункта есть вложенные пункты на другие файлы, этот пункт — одна глава, а файлы его пунктов — подглавы `NNN-01`, `NNN-02`, … по порядку чтения, даже если подглава одна. Тогда ссылка `003-02 ¶12` работает и на таких книгах. Пример:

```
Оглавление книги        parts/                 Заголовок в book.md
Preface                 001.md                 Preface
Volume One
  Part One              002-01.md, 002-02.md   Volume One. Part One
    Chapter 1
    Chapter 2
  Part Two              003-01.md              Volume One. Part Two
    Chapter 3
```

- **Тома** — пункты над частями — идут в начало названия главы через «. »: «Volume One. Part One». Пункт над всей книгой (полутитул с её названием над всеми частями) в названия не идёт.
- **Название главы** — в `book.md` и строкой `# …` в начале её первой части. В подглаве её заголовок — `##` (первый заголовок файла, а если в начале файла его нет — текст пункта оглавления), заголовки внутри — `###`, на части они не делят.
- **Страница части или тома**, где кроме заголовка ничего нет (или подзаголовок, который уже есть в пункте оглавления: «Part I» и «1805» при пункте «Part I: 1805»), частью не становится: она в «Пропущено» с причиной «заголовок части — в названии главы» — и с ключом `--all` тоже. Страница части с текстом — `NNN-00` «Начало главы»; страница тома с текстом — отдельная глава перед главами тома. Если первый пункт части ведёт в файл самой части (`part1.xhtml#ch1`, как у Project Gutenberg), этот файл — первая подглава `NNN-01` (без заголовка части). Страница части, пропущенная как служебная, — название главы всё равно по пункту оглавления.
- **Файл без пункта в оглавлении** между двумя главами одной части (Calibre режет длинные главы на куски) — продолжение предыдущей подглавы, без своего номера.
- Пункты на файлы вне порядка чтения и с `linear="no"` не учитываются. Служебные страницы, «Пропущено» и сноски — как раньше; сноски нумеруются в каждой части свои.
- Если оглавление не совпадает с порядком чтения (глава одной части стоит среди файлов другой или один файл — в двух частях), оно не используется: главы — по файлам, как раньше, а команда пишет «Предупреждение: оглавление EPUB не совпадает с порядком чтения — главы по файлам».

Принятая ошибка: последняя глава последней части, разрезанная на куски (как выше), даст лишнюю главу — после последнего файла части файл без пункта уже не считается её продолжением и становится отдельной главой.

### Книга одним файлом

Сайты-библиотеки и конвертеры из FB2 часто кладут всю книгу в один файл, а первым заголовком в нём пишут название книги. Тогда главы — по заголовкам внутри файла, а не одна глава на всю книгу, и ссылка `003-02 ¶12` работает и на таких книгах. Правило действует, когда выполнено всё разом:

- после отбора служебных страниц (обложка, титул, …) и файла примечаний в книге остался ровно один файл с текстом; с ключом `--all` служебные страницы с текстом остаются — тогда файлов больше одного и правило не действует;
- файл начинается заголовком, который совпадает с названием книги из её данных: по буквам и цифрам без учёта регистра одно содержит другое («КНИГА!» и «Книга. Роман» — совпадают); сноски в этом заголовке нет;
- после названия есть уровень заголовков, который встречается два раза и больше.

Как режется:

- **Название книги** в части не идёт: оно в `book.md`, как у любой книги.
- **Уровень глав** — самый верхний из повторяющихся после названия. Каждый заголовок этого уровня или выше начинает главу; более высокий заголовок в конце файла («Примечания» после глав `h2`) — тоже своя глава.
- **Внутри главы** — подглавы по заголовкам, как у главы-файла: `NNN-00` — текст до первой подглавы, мелкие заголовки — `###`.
- **Текст между названием и первой главой** — глава `001`; её название — её первый заголовок («Эпиграф»), а если его нет — первые слова.

Пример:

```
Файл книги                    parts/
Название книги (h1)
Абзац                         001.md
Вступление (h2)               002.md
Часть первая (h2)             003-00.md — текст до первой главы части
  Глава 1 (h3)                003-01.md
  Глава 2 (h3)                003-02.md
Часть вторая (h2)
  Глава 3 (h3)                004-01.md
  Глава 4 (h3)                004-02.md
Заключение (h2)               005.md
```

Остальные книги — как раньше. Сноски, служебные страницы и «Пропущено» — как у любой книги; сноски нумеруются в каждой части свои.

Принятые ошибки:

- книга, разрезанная конвертером на файлы по размеру (`index_split_000.html`, `index_split_001.html`, …), — главы по файлам, как раньше;
- первый заголовок файла — не название книги (или в нём сноска) — как раньше: одна глава, подглавы по заголовкам;
- заголовок, за которым до следующей главы нет текста («Часть первая» прямо перед «Глава 1» того же уровня), частью не становится, и в книге его не видно;
- примечания в конце того же файла с заголовком на каждое (вид книг из FB2) — глава «Примечания» с подглавой на каждое примечание.

### Сноски

Сноска, текст которой лежит в той же главе (EPUB 3 `aside`, блок примечаний в конце главы, примечание после абзаца) или в отдельном файле книги (файл «Примечания» в конце, файл примечаний на каждую главу, EPUB 3 endnotes), в части выглядит как сноска markdown: в абзаце — метка `слово[^1]`, а в самом конце файла части — определения одним блоком:

```
…последний абзац.

[^1]: Текст сноски.
[^2]: Другая сноска.
```

- Номера меток — по первому появлению в файле части сверху вниз, с 1 (заголовки тоже считаются), одним рядом для сносок из той же главы и из файла примечаний. Несколько ссылок на одно примечание в одной части — одна метка; если глава разбита на подглавы, в каждой части свои метки и свои определения. На одно примечание ссылаются две главы — в каждой своя метка и своё определение.
- Из текста главы или файла примечаний примечание уходит; раздел «Примечания» целиком (заголовок, `---`, список) — тоже, если в нём больше ничего нет. Примечание, на которое не ведёт ни одна сноска, остаётся обычным текстом там, где стоит.
- Файл примечаний, из которого все примечания разнесены по главам (остались только заголовки и разделители), частью не становится и не сдвигает номера глав: он виден в `book.md` в разделе «Пропущено» с причиной «примечания — разнесены по частям» — и с ключом `--all` тоже. Если в нём остался текст (например, комментарий переводчика, на который нет ссылок), он остаётся главой с этим текстом.
- Текст сноски — одна строка: курсив и жирный сохранены, несколько блоков и переносы строк — через пробел; обратная ссылка («↩») и ведущий знак (`1`, `[1]`, `1.`, `1)`, `*`) убраны.
- Сноской считается ссылка на примечание с пометкой сноски (`epub:type="noteref"`, `role="doc-noteref"`) или с номером (`1`, `[1]`, `1)`, `1.`, `*`, `†`) в верхнем индексе. Примечание может лежать в этом же документе или в другом файле книги из порядка чтения (`notes.xhtml#n1`, `../Text/notes.xhtml#n1`). Если в другом файле цель — не сам абзац или пункт с этим `id`, а пустой якорь в начале абзаца (`<p><a id="n1"></a>…`), это примечание, только когда в нём есть обратная ссылка в главу, откуда сноска: иначе это ссылка на абзац главы, и абзац остаётся на месте. Ссылка на раздел с заголовками, ссылка на файл без `#`, на файл вне порядка чтения и на служебную страницу (даже с `--all`) — не сноска, текст ссылки остаётся в тексте как был.
- Сноска в заголовке остаётся меткой в файле части (`# Глава 1[^1]`), а в `book.md` заголовок — без метки.
- Сноски не сдвигают номера абзацев `¶` (раздел «Ссылки на место»).

Пока нет:

- примечание с заголовком внутри (`<div id="n_1"><h3>1</h3><p>…</p></div>`, так делают конвертеры из FB2) — не сноска: номер остаётся слитно со словом, файл примечаний — отдельной частью;
- Calibre иногда ставит примечания прямо в конец последней главы, без отдельного файла: сноски разбираются, а заголовок «Примечания» остаётся подзаголовком последней главы;
- примечания, развёрнутые прямо в тексте простым текстом без ссылок (`слово[N - текст]`), и список примечаний в конце без `id` — не сноски: остаются текстом как есть.

Служебные страницы издания — обложка, полутитул (с разметкой `halftitlepage`, как у Standard Ebooks), титульный лист, выходные данные (©, ISBN, УДК/ББК; страница издательства с разметкой `imprint`, как у Standard Ebooks), оглавление самой книги — тоже не становятся частями, чтобы не сбивать нумерацию глав. Их видно по разметке файла книги, а если её нет — по признакам: короткая страница с выходными данными (аннотация на той же странице пропускается вместе с ними), страница из одних ссылок на главы, короткая страница с названием книги. В сомнительных случаях страница остаётся: «Часть первая», посвящение, эпиграф, предисловие, примечания не пропускаются (кроме файла примечаний, разнесённого по частям, — раздел «Сноски»). Что пропущено и почему, видно в `book.md` — в разделе «Пропущено» под оглавлением: файл в архиве, первые слова страницы, причина. Там же, на своём месте в порядке чтения, — страницы без текста (обложка из одной картинки, пустая страница, один разделитель): пустая ячейка «Начало» и причина «нет текста»; частями они не становятся и не сдвигают номера глав — и с ключом `--all` тоже. Если импорт ошибся, возьмите всё без пропусков ключом `--all` (в любом месте после `--`):

```
npm run import -- книга.epub out/книга --all
```

Если служебными оказались все страницы, команда так и пишет и ничего не создаёт. Если файл не EPUB или архив повреждён, команда пишет, в чём дело, и ничего не создаёт. Папка назначения должна быть новой или пустой: в папку с файлами импорт не пишет, чтобы ничего не перезаписать.

Раскладка `book.md` + `parts/` — черновая; окончательную раскладку книги в библиотеке утвердит владелец.

## Импорт FB2

FB2 и FB2 в zip — та же команда (решение Б-14 в `docs/решения.md`):

```
npm run import -- книга.fb2 out/книга
npm run import -- книга.fb2.zip out/книга
```

Получится та же папка, что из EPUB: `book.md` и `parts/`. Конвертировать FB2 в EPUB не нужно.

- **Формат** — по содержимому: XML, где первый элемент — `FictionBook`. Zip — FB2, если в нём нет `META-INF/container.xml` и ровно один файл `.fb2` (в любой папке архива); два `.fb2` и больше — ошибка «в архиве несколько книг FB2 — распакуйте нужную»; иначе zip разбирается как EPUB.
- **Кодировка** — из первой строки файла (`encoding="windows-1251"` и другие); нет — UTF-8. Неизвестная кодировка и повреждённый XML — команда пишет, в чём дело, и ничего не создаёт.
- **`book.md`** — из описания книги в файле: название, автор («Имя Отчество Фамилия» — что есть; только псевдоним — он; несколько — через запятую), язык, переводчик — так же, как автор; издатель, год и ISBN — из сведений об издании, с теми же проверками, что у EPUB (ненастоящий год и ISBN с неверной контрольной цифрой не пишутся). Чего нет — «не указан». В «Пропущено» попадают только примечания, разнесённые по частям (ниже, «Сноски»); ключ `--all` ничего не меняет.

Главы:

- **Главы** — разделы (секции) верхнего уровня основного текста книги; заголовок главы — `#` в начале её первой части. Название книги в начале текста в части не идёт.
- **Подглавы** — вложенные разделы: `NNN-01`, `NNN-02`, … (заголовок — `##`), даже если вложенный раздел один; текст до первого вложенного — `NNN-00`. Разделы глубже — заголовки `###`, на части не делят. Без вложенных разделов глава — одна часть `NNN.md`.
- **Текст до первого раздела** (эпиграф книги) — глава `001` без заголовка; в оглавлении — первые слова.
- **Обёртка:** если в книге один раздел верхнего уровня, а в нём два и больше вложенных, главы — вложенные разделы; заголовок обёртки в части не идёт, её текст до первой главы — в главу `001` вместе с эпиграфом книги.
- Раздел без заголовка — в оглавлении первые слова, строки `#`/`##` в части нет. Заголовок из нескольких строк — одной строкой: через «. », а после знака препинания — через пробел. Пустой раздел (только заголовок) частью не становится.
- **Примечания** и другие отдельные тексты книги (в FB2 — `body` с именем `notes`, `comments` и т. п.) — главами в конце, каждый одной частью: их разделы — заголовками `###`. Название главы — заголовок этого текста, нет его — «Примечания» (тогда строки `#` в части нет). Примечания, на которые ведут сноски, отсюда уходят (ниже, «Сноски»): глава остаётся, только если в ней остался текст.

Пример:

```
Файл книги                         parts/
Название книги                     — (в book.md)
Эпиграф                            001.md
Раздел «Первая»                    002.md
Раздел «Вторая»: текст             003-00.md
  Раздел «А»                       003-01.md
    Раздел «Мелкий»                «### Мелкий» в 003-01.md
  Раздел «Б»                       003-02.md
Примечания без ссылок на них       004.md
```

Сноски — как у EPUB (раздел «Сноски» выше, решение Б-15): в абзаце — метка `слово[^1]`, в конце файла части — определения одним блоком.

- **Сноска** — ссылка из основного текста книги на раздел текста примечаний (`body` с именем `notes` или `comments`), на любой глубине: примечания могут быть сгруппированы по главам. Пометка сноски (`type="note"`) не нужна, префикс ссылки — любой (`l:href`, `xlink:href`). Текст ссылки (номер) и пробелы перед ним в абзац не идут.
- **Определение** — текст раздела-примечания без его заголовка (номера), одной строкой: курсив и жирный сохранены, несколько абзацев и строки стихов — через пробел.
- Номера меток — свои в каждой части, по первому появлению; несколько ссылок на одно примечание в одной части — одна метка. Сноска в заголовке — метка в строке `#`/`##` части, а в `book.md` заголовок без неё.
- Не сноски, текст ссылки остаётся в абзаце: ссылка на `id`, которого в примечаниях нет; ссылка на место в самом тексте книги; ссылка наружу (`http…`); ссылки внутри примечаний — на другое примечание и обратно в текст.
- Примечание, на которое ведёт сноска, из текста примечаний уходит; примечания без ссылок на них остаются там же, главой в конце. Если в тексте примечаний не осталось ничего, кроме заголовков, главой он не становится: в `book.md` в разделе «Пропущено» — строка `body:notes` (или `body:comments`), первые слова примечаний и причина «примечания — разнесены по частям».
- Строка «Сносок» в `book.md` — число определений во всех частях. Сноски не сдвигают номера абзацев `¶`.

Текст:

- Абзац — абзац; курсив — `*…*`, жирный — `**…**`, код — `` `…` ``; зачёркнутый, верхний и нижний индекс, оформление и ссылки — просто текстом.
- Подзаголовок внутри главы — `###`, части не делит.
- Эпиграф и цитата — как цитата у EPUB: строки с `> `, один абзац; автор — строкой цитаты.
- Стихи: заголовок стиха — `###`, строфа — один абзац, строки — через перенос строки; автор и дата — абзацами.
- Таблица — один абзац: строки через перенос, ячейки через ` | `.
- Номера абзацев `¶` считаются так же, как у EPUB (раздел «Ссылки на место»).

Не импортируются: аннотация, обложка и картинки, оформление. Другие версии формата (FB2 3.0) не проверялись.

## Импорт PDF

PDF с текстовым слоем (не скан) — та же команда:

```
npm run import -- книга.pdf out/книга
```

Формат определяется по содержимому файла, а не по расширению. Получится та же папка, что из EPUB: `book.md` и `parts/`.

- Главы и подглавы — по закладкам PDF (оглавление сбоку в программе просмотра): закладка верхнего уровня — глава, вложенная в неё — подглава (`003-01`, `003-02`, …, даже если она одна; текст до первой подглавы — `003-00`). Закладки глубже не делят текст. Текст до первой закладки (титул, аннотация) — отдельной главой «До первой закладки».
- Заголовок главы — `#` из закладки, подглавы — `##`; напечатанный на странице такой же заголовок в тексте не повторяется.
- PDF без закладок — главы и подглавы по заголовкам, набранным крупнее основного текста; команда предупреждает: «главы размечены по крупному шрифту, проверьте оглавление в book.md». Правило:
  - размер строки — тот, которым набрано больше всего её букв (поднятая буквица строку крупной не делает); размеры, отличающиеся меньше чем на 5 %, считаются одним;
  - основной размер — тот, которым набрано больше всего букв книги (без колонтитулов и номеров страниц);
  - строка заголовка — не мельче 1,1 × основного (Word набирает заголовки 14 при тексте 12), не длиннее 120 знаков, не из одной буквы (кроме римских `I`, `V`, `X`) и не строка оглавления с номером страницы после отточия; заголовок — до трёх таких строк подряд одним размером на одной странице, больше трёх — текст крупным шрифтом;
  - строки заголовка склеиваются через пробел, после номера — через «. » (`Chapter 1` + `Beginning` → «Chapter 1. Beginning»); номер отдельной строкой склеивается со следующим заголовком: «1» + «Начало» → «1. Начало»;
  - заголовок с тем же текстом, что прошлый того же размера (крупный колонтитул главы), идёт текстом;
  - уровень — размер, которым набраны хотя бы два разных заголовка на разных страницах: самый крупный уровень — главы (`#`), следующий — подглавы (`##`), части — как у закладок. Остальные заголовки (название книги и автор на титуле) текст не делят и стоят в нём строкой `### …`. Подглава до первой главы — глава сама по себе; текст до первого заголовка — отдельной главой «До первого заголовка»;
  - уровней нет — книга одной главой «Текст», команда предупреждает, что главы не размечены.
- Принятые ошибки разметки по шрифту: оглавление книги, набранное крупно, но без номеров страниц, может дать лишние главы; заголовок, перешедший на следующую страницу, — два заголовка; заголовки основным размером, выделенные только жирным или капителью, не находятся; длинный заголовок, перенесённый после числа (`Записки 1812` + `года`), склеится через «. »; строки чуть крупнее основного (1,1–1,2 ×), набранные так не как заголовок (эпиграф, выделенная цитата), могут стать заголовками: если такие строки с разным текстом есть на двух и больше страницах, это уровень — при более крупных главах подглавы `##`, и глава делится на части.
- Абзацы собираются из строк страницы: новый абзац — после увеличенного промежутка между строками или по отступу первой строки; абзац, который переходит на следующую страницу, остаётся одним абзацем.
- Колонтитулы убираются: строка у верхнего или нижнего края страницы (в полосе 8 % её высоты), которая без учёта цифр повторяется у того же края на половине страниц книги и больше — или на половине чётных, или нечётных (слева автор, справа название). В книге меньше 4 страниц колонтитулы не ищутся.
  - Колонтитул с номером страницы, который на отдельной странице стоит у другого края (так бывает на первой странице у Word), тоже убирается: тот же текст с числами на тех же местах, и номер продолжает ряд колонтитула. Та же строка без номера или с числом не из ряда (титул с названием книги) остаётся.
- Номера страниц убираются: число у края страницы (или «— 12 —», «12 / 300»), если на соседней странице номер идёт подряд. Число у края, которое ряд не продолжает (год, номер сноски), остаётся.
- Переносы склеиваются. Строка абзаца или заголовка кончается буквой и дефисом, следующая начинается с буквы — слово разорвано:
  - следующая начинается с прописной, а часть до дефиса — не вся из прописных: дефис остаётся, пробела нет (`Петров-` + `Водкин` → `Петров-Водкин`);
  - иначе решает сама книга — как это слово в ней написано не на переносе, без учёта регистра: через дефис есть, а слитно нет — дефис остаётся (`какой-` + `нибудь` → `какой-нибудь`, если в книге где-то есть «какой-нибудь»); иначе — без дефиса (`пере-` + `носах` → `переносах`). Так же и в заголовке капсом: `ПЕРЕ-` + `НОСАХ` → `ПЕРЕНОСАХ`;
  - в счёт идут слова всего текста книги без колонтитулов и номеров страниц, кроме самих разорванных слов (последнего слова строки с дефисом и первого слова следующей); частью слова считаются только буквы перед дефисом и после него — скобки и кавычки нет;
  - следующая строка начинается не с буквы (цифра, кавычка, тире) — склеивается через пробел, дефис остаётся.

  Мягкие переносы убираются. Принятая ошибка: составное слово, которое в книге больше нигде не пишется через дефис (`well-` + `known`, а «well-known» в книге больше нет), склеится без дефиса; так же — если слово в книге пишется и слитно, и через дефис.
- В `book.md` название и автор — из сведений самого PDF; переводчик, издатель, год, ISBN — «не указан». Раздела «Пропущено» нет, ключ `--all` для PDF ничего не меняет.

Что пока не поддерживается:

- сканы (PDF без текстового слоя) — команда так и пишет и ничего не создаёт;
- сноски остаются в тексте;
- перенос мягким дефисом (U+00AD) в конце строки библиотека чтения PDF не отдаёт — такое слово остаётся разорванным пробелом: `пере носах`;
- PDF с паролем — команда пишет, что нужен пароль, и ничего не создаёт (защищённый без пароля на открытие читается как обычный).

## Распаковка архива

Большую книгу присылают архивом — zip, 7z или rar. Его сначала распаковывают, потом импортируют файл книги (решение Б-18 в `docs/решения.md`). Из корня репо:

```
npm run unpack -- книга.7z out/распаковано
```

Команда пишет, что распаковала; файлы книги (`.epub`, `.pdf`, `.fb2`, `.fb2.zip`) помечены «книга»:

```
Готово: 7z, файлов: 2.
книга  /…/out/распаковано/Книга.pdf  212.4 МБ
       /…/out/распаковано/обложка.jpg  84 КБ
```

- Формат — по содержимому файла, а не по расширению. Распаковывает 7-Zip, собранный в WASM (зависимость `7z-wasm`): других программ не нужно.
- Папка назначения — новая или пустая, как у импорта. Пути с `..` и абсолютные остаются внутри неё. Ссылки не переносятся, а архив со ссылкой наружу (`/etc/…`, `../…`) не распаковывается целиком.
- Имена в zip, записанные не в UTF-8 (cp866 старых архиваторов), приходят искажёнными и без расширения; PDF и FB2 всё равно помечены «книга» — по содержимому, импорт тоже узнаёт формат по содержимому.
- EPUB — тоже zip, но его не распаковывают: команда так и пишет — импортируйте его как есть.
- Архив с паролем, повреждённый, пустой или не zip/7z/rar — команда пишет, в чём дело, и ничего не создаёт. Нет в архиве файла книги — предупреждение.
- Архив распаковывается в памяти: архивы в гигабайты не для этой команды.

## Порция кусок за куском

Большую книгу можно вводить порциями: кусок текста (файл или вставка) становится следующей главой уже импортированной книги (решение Б-09 в `docs/решения.md`). Из корня репо:

```
npm run import -- --append кусок.txt out/книга
npm run import -- --append - out/книга
```

`-` — текст из вставки: вставьте его в терминал и нажмите Ctrl-D в начале пустой строки. Ключи — в любом месте после `--`: `--title "…"` — свой заголовок части, `--again` — дописать повтор (ниже). Значение ключа — отдельным аргументом (`--title "Глава 5"`, а не `--title=Глава 5`).

- **Кусок** — простой текст или markdown в UTF-8 (BOM и переводы строк Windows не мешают). EPUB, PDF и FB2 порцией не дописываются: импортируйте файл целиком в отдельную папку, а кусок возьмите из её части.
- **Заголовок части** — первая непустая строка куска, если она начинается с `# ` (`##` и глубже — нет); эта строка уходит из текста. `--title "…"` важнее неё. Нет ни того, ни другого — «Без названия». В оглавлении заголовок — без меток сносок `[^N]`.
- **Абзацы.** Есть в куске пустые строки (строка из пробелов — тоже пустая) — абзацы делятся только по ним, перенос строки внутри абзаца остаётся, несколько пустых строк подряд — одна. Пустых строк нет — каждая строка становится абзацем; пустая строка сразу после заголовка, в начале и в конце куска не в счёт. В обоих случаях блок кода в ```` ``` ```` — один блок, строки заголовков (`## Раздел`) и разделители (`---`, `***`, `* * *`) — отдельным блоком, пробелы в конце строк убираются. Строки `[^N]: …` подряд в конце куска без пустых строк — определения сносок одним блоком (они не абзацы и прибавляются к «Сносок» в `book.md`). Число слов в строке оглавления — без меток `[^N]:`, текст сносок считается.
- **Номер части** — следующий после последней главы в оглавлении `book.md`: после `003` или `003-00…003-02` — `004.md`. Часть — всегда целиком, без подглав. Готовые части и номера их абзацев не меняются; в `book.md` добавляется строка оглавления (перед «Пропущено»), «Глав» и «Частей» — плюс один, остальное — байт в байт.
- **Повтор.** Если текст куска совпадает с текстом одной из прежних частей (без строки заголовка), команда пишет «такой кусок уже есть: часть NNN» и ничего не дописывает. Если повтор нужен, — ключ `--again`.
- **Новая книга.** Первый кусок может завести книгу в новой или пустой папке — тогда нужно название, автор по желанию:

  ```
  npm run import -- --append кусок.txt out/книга --book-title "Название" --author "Автор"
  ```

  В `book.md` язык и данные издания — «не указан», кусок — `001.md`. С `--book-title` или `--author` в папку готовой книги команда не пишет: «книга уже заведена — не та папка?».

Если что-то не так — папка без `book.md`, оглавление `book.md` не сходится с `parts/`, кусок пуст или не в UTF-8, глав уже 999, — команда пишет, в чём дело, и папка остаётся как была.

## Ссылки на место

Ссылка на место в книге — часть и номер абзаца: `003-02 ¶12` — часть 003-02, двенадцатый абзац; `003 ¶1–40` — абзацы с 1 по 40 части 003. Часть — как в оглавлении: `NNN` или `NNN-MM`.

Как считаются абзацы — по файлу части `parts/NNN[-MM].md`:

- файл делится на блоки по пустой строке (строка из одних пробелов — тоже пустая);
- блок кода от строки ```` ``` ```` до закрывающей ```` ``` ```` — один блок, пустые строки и `#` внутри него ничего не делят;
- не считаются заголовки — блоки, которые начинаются с `#`…`######` и пробела (`#1 в списке` — абзац), и разделители — блок из одного `---`, `***` или `* * *`;
- блок в самом конце файла, где каждая строка начинается с `[^` + цифры + `]: `, — определения сносок (решение Б-07): не абзац, номеров не сдвигает; метка `[^1]` внутри абзаца — часть абзаца;
- остальные блоки — абзацы, по порядку с 1. Список, таблица и цитата — один абзац.

Номера в текст не вписываются: их показывает команда, она и есть мерило. Из корня репо:

```
npm run show -- out/книга 003-02
npm run show -- out/книга 003-02 ¶12
npm run show -- out/книга 003-02 ¶3–5
```

Без номера — вся часть: каждый абзац начинается с номера (`¶1 Текст…`), заголовки, разделители и блок определений сносок — как есть, без номера. С номером — только этот абзац; с диапазоном (тире или дефис) — абзацы диапазона и заголовки с разделителями между ними. Ссылку можно вставить и целиком, как из разбора: `npm run show -- out/книга "003-02 ¶12"` или `003-02¶12`.

Номер без `¶`, часть не того вида, нет такой части, папки книги или абзаца — команда пишет, в чём дело (сколько абзацев в части; на какие части разбита глава, если просили главу целиком), и ничего не показывает.

Правка текста части сдвигает номера, поэтому файлы в `parts/` руками не правятся (решение Б-04 в `docs/решения.md`).

## Сессия чтения

Книги читаются в облачной сессии Claude Code, к которой подключены оба репо: `book-agent` (этот — навыки и команды) — первым, основным: навыки берутся из него; и закрытый `book-library` (книги, разборы, справочники). Метод — `docs/чтение.md`; навыки (решение Б-16):

- `book-intake` — приём книги: загрузите файл книги (EPUB, PDF, FB2 или архив zip / 7z / rar) — сессия сама распакует его, импортирует пробно, проверит оглавление, предложит имя папки и, с вашего слова, импортирует в `books/<папка>/`, заведёт паспорт, журнал и справочники. Исходный файл в git не идёт — храните его у себя;
- `reading` — разбор порции: саммари со ссылками на абзацы, изменения для справочников, разбор, вопросы, спор;
- `reading-retro` — ретро порции: справочники, закрытие разбора, журнал и замеры.

Общие правила навыков — `.claude/reading/rules.md`; шаблоны — в папках `templates/` навыков, правила библиотеки — `book-intake/templates/library-CLAUDE.md` (первая сессия чтения кладёт их в `book-library`). Работу сессия сохраняет коммитом сразу в `main` библиотеки (решение Б-17) — поэтому в промпте сессии чтения нужно разрешить push в `main` `book-library`.
